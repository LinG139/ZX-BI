# 可行性分析报告

## 智析云 —— 基于AIGC的智能数据分析平台

---

## 一、项目需求分析概况

本项目拟构建一个面向中小企业和个人用户的AI驱动智能数据分析平台，用户只需上传原始数据集并输入分析诉求，即可自动生成专业可视化图表及分析结论。

核心需求包括：智能图表生成（自然语言交互+AI自动分析）、多模式处理架构（同步/异步/RabbitMQ三种模式）、多AI供应商适配（智谱AI、鱼聪明AI等）、用户积分系统与限流控制、图表全生命周期管理（创建、查询、编辑、删除）、社区互动功能（帖子发布、点赞、收藏、全文搜索）。

系统采用前后端分离架构，后端基于Spring Boot + MyBatis-Plus，前端基于React + Umi + Ant Design。核心技术组件包括RabbitMQ消息队列、Redis分布式缓存、Redisson滑动窗口限流、智谱AI SDK等。

从需求角度看，数据分析是现代企业决策的核心需求，AI驱动的零门槛BI工具存在明显市场空白，项目需求真实且迫切。

---

## 二、可行性要素分析

### 2.1 技术可行性

后端采用Spring Boot 2.7.x + MyBatis-Plus 3.5.x，前端采用React 18 + Umi 4 + Ant Design 5.x，均为业界成熟技术栈。AI接入层基于智谱AI官方SDK（oapi-java-sdk），配合AiManager抽象层实现多供应商动态切换。RabbitMQ消息队列实现异步任务处理，Redisson实现分布式限流。数据存储采用MySQL 5.7+，缓存采用Redis 6.0+。

关键技术路径（Excel解析、AI图表生成、MQ异步处理、限流控制）均有明确实现方案。图表生成流程为：用户上传CSV数据 → 构建分析Prompt → 调用AI API → 解析JSON响应 → 生成ECharts配置 → 前端渲染。异步模式通过RabbitMQ消息队列实现任务排队和消费者处理。整体技术方案成熟可靠，无技术障碍。

### 2.2 经济可行性

开发阶段工具全部免费（IntelliJ IDEA社区版/VS Code/Git/Maven/Node.js），无第三方软件采购需求。技术栈均为开源或免费方案：Spring Boot、MyBatis-Plus、RabbitMQ、Redis、React、Ant Design等。

运营成本方面，用户自付AI API调用费用，平台提供积分充值模式。项目开发阶段零资金投入，运营阶段年成本约3050-10500元（云服务器、域名、数据库等）。如采用用户自备API密钥模式，平台可实现零运营成本。总体来看，项目开发与运营成本极低，经济上高度可行。

### 2.3 操作可行性

系统以Web应用形式呈现，用户通过浏览器直接访问，无需安装客户端。智能分析页提供数据上传、分析目标输入、图表预览三个步骤，操作流程清晰直观。Umi + Ant Design企业级前端框架确保界面专业美观，符合用户操作习惯。

目标用户群体（中小企业运营人员、互联网产品/运营团队、高校师生等）普遍具备基本的计算机操作能力。从操作角度来看，使用本系统不存在操作障碍。

### 2.4 法律可行性

项目代码基于开源模板开发，业务代码为团队原创，拟以MIT或Apache 2.0协议开源发布。提示词模板为团队原创设计，属于核心知识产权。系统数据存储于自有服务器MySQL数据库，用户认证基于Spring Session + Redis，数据按用户ID隔离。生产环境强制HTTPS加密传输，后端对用户输入进行严格校验。平台不收集用户敏感数据，符合个人信息保护法规要求。

## 三、项目设计方案

### 3.1 系统架构

系统采用前后端分离架构。前端为React SPA单页应用，基于Umi脚手架和Ant Design组件库构建，包含智能分析页、异步分析页、MQ分析页、我的图表、AI聊天室、用户中心等模块。后端为Spring Boot RESTful API服务，提供用户管理、图表生成、文件处理、AI对话、帖子管理等接口。

核心业务流程：客户端上传CSV数据并输入分析诉求，后端保存原始数据，通过AiManager调用AI服务生成图表配置，异步模式下通过RabbitMQ消息队列实现高并发处理。

### 3.2 核心模块设计

**智能分析引擎**：支持同步、异步、MQ三种模式。同步模式适用于简单分析任务，同步返回结果；异步模式通过线程池处理，适用于中等复杂度任务；MQ模式通过RabbitMQ实现，适用于高并发场景。

**多AI供应商适配**：通过AiManager抽象层统一管理AI调用，根据配置动态切换智谱AI、鱼聪明AI等供应商。提示词模板与业务逻辑分离，便于维护和优化。

**限流控制**：基于Redisson实现滑动窗口限流，配合用户积分系统控制调用频次，防止恶意刷接口。

**定时任务**：通过Spring Scheduler实现失败图表自动重试补偿，提升系统可靠性。

## 四、人员配置和培训计划

### 4.1 人员配置

项目采用精简的小团队模式。核心人员配置为1-2人：项目负责人1人（兼任架构设计和验收），全栈开发1-2人（可兼任前后端开发）。测试和文档维护工作由开发人员兼任。

### 4.2 培训计划

开发人员需熟悉以下技术栈（预计培训时间3-5天）：
- Spring Boot 2.7.x + MyBatis-Plus 3.5.x（1天）
- React 18 + Umi 4 + Ant Design 5.x（1天）
- RabbitMQ消息队列（0.5天）
- Redis + Redisson分布式缓存（0.5天）
- 智谱AI SDK集成（0.5天）
- 项目代码规范和架构（0.5天）

用户端无需专门培训，系统提供直观的操作引导和示例数据。

## 五、项目主要风险

| 风险 | 可能性 | 影响 | 应对策略 |
|:---|:---|:---|:---|
| AI服务中断或API变更 | 中 | 高 | 多供应商适配，支持运行时动态切换 |
| AI生成图表格式不稳定 | 中 | 中 | 后端异常处理+三级JSON解析兜底 |
| RabbitMQ消息堆积 | 低 | 中 | 消费者限流+队列监控告警 |
| 高并发导致系统过载 | 中 | 中 | Redisson滑动窗口限流+积分控制 |
| 用户上传恶意数据 | 低 | 中 | 后端输入校验+文件大小限制 |
| Redis/MySQL服务故障 | 低 | 高 | 异常捕获+降级策略 |

以上风险均已制定应对措施，整体风险可控。

## 六、可行性研究的结论和建议

综合评估，本项目在技术上采用成熟稳定的技术栈，关键路径无技术障碍；经济上开发运营成本极低，无需外部资金注入；操作上用户学习曲线平缓，使用门槛低；法律上不涉及知识产权纠纷和数据合规风险。主要风险均已识别并制定了缓解措施。

**结论：项目具有高可行性，建议启动实施。**

实施建议：
- 采用Spring Boot + React前后端分离技术栈
- 按迭代增量式开发策略，分阶段交付（M1-M7）
- 提示词模板与业务逻辑严格分离，预留多AI供应商扩展接口
- 优先实现同步模式核心流程，再逐步扩展异步和MQ模式
- 建立版本发布检查清单，确保文档与代码同步更新

## 七、其他重要意见

本项目的核心差异化在于"智能化"而非"大而全"——通过自然语言交互和AI自动分析降低数据分析门槛，而非追求复杂的配置选项。架构上应重点保障可扩展性，为后续社区化模块分享和高级图表模板预留演进空间。

建议项目以GitHub开源形式首发，借助社区力量迭代优化，在用户规模和反馈成熟后再评估商业化路径（积分充值、API代理、增值订阅等）。
